# Coffee Cellar

iPhoneで長期保管中のコーヒー豆を管理する個人用PWAです。HTML / CSS / JavaScriptで動き、データは端末内のIndexedDBに保存します。

**公開URL：[Coffee Cellar](https://tanyeee.github.io/CoffeeStrage/)**

## 機能

- 豆の追加・一覧・詳細・編集、焙煎度1〜5と自由入力
- 開封状態は一覧に「開封」列として表示（開封日・不明・未開封）
- 在庫の並び順は「豆別 / 古い順 / 新しい順」の3種類（スマホでは下部ドック左端のメニューで切替）
- アーカイブも「豆別 / 終了が新しい順 / 終了が古い順」に対応。豆別では保管期間とアーカイブ日を袋ごとに表示
- 豆別まとめでは同じ豆を1枚に集約し、各袋を経過・焙煎度・短い日付の1行で表示
- 経過は1ヶ月未満が「24日」、1年未満が「7.5ヶ月」（0.1ヶ月単位で切り捨て）、1年以上が「1年8ヶ月」。総日数は詳細画面のみ表示（1ヶ月未満は省略）
- 「全期間 / 1ヶ月以上 / 半年以上」の期間フィルター（焙煎日から満了した暦月で判定）
- 在庫は「すべて / 開封 / 未開封」のボタンと期間メニューで絞り込み。スマホでは並び順・期間・開封ボタンを右寄せの下部ドックに配置し、ヘッダーに絞り込み前の現在の貯蔵数を表示
- アーカイブは豆名・終了期間・終了区分で絞り込み、豆名と備考を検索（検索欄は入力時に展開）
- 詳細画面から開封日を記録（カレンダー選択・日付不明・未開封に戻す）
- 袋ごとの備考（譲渡や味の記録）：詳細の「編集」から在庫・アーカイブとも追記可能。一覧には表示しません
- アーカイブ時に「飲み切った / 人に譲渡 / 廃棄した」を記録し、後から編集可能。確認付き完全削除
- プリセット名のタップで編集・削除、≡ハンドルで手動並べ替え
- プリセット名の変更は、紐付いた在庫・アーカイブの豆名にも連動
- おすすめタブで、未開封の目標袋数と飲み切り履歴から補充候補を表示
- プリセットと焙煎度から、記録の少ない新しい組み合わせを提案（現在の在庫にある組み合わせは除外）
- 購入日は任意で記録し、豆の詳細とCSVに含める。消費ペースの計測開始日とおすすめ条件は端末内に保存
- JSONバックアップ・内容確認付き全置換復元
- 在庫とアーカイブのCSV書き出し（UTF-8 BOM付き、Excel等の閲覧用）
- ホーム画面追加、初回準備後のオフライン起動・操作

プリセットは「エチオピア｜イルガチェフィー G1 ブナブナ」のように区切ります。DB v4への更新時に、既存の豆と一致するプリセットを紐付けます。以前の標準名（区切り線を入れる前）も対応し、登録日時・焙煎日・状態・袋数を保持します。曖昧な名前の推測はしません。

## 豆別まとめとプリセット管理

在庫・アーカイブとも初期表示は「豆別」です。同名の袋は1枚のカードにまとめ、カードの順序はプリセットの手動順になります。在庫のカード内は焙煎日の古い順、アーカイブはアーカイブ日の新しい順です。未登録の豆名は後ろにまとめます。各行をタップするとその袋の詳細を開けます。在庫は「古い順 / 新しい順」、アーカイブは「終了が新しい順 / 終了が古い順」で袋を1件ずつ表示します。アーカイブの豆フィルターは並び順の左に配置します。絞り込み・表示方法は画面を往復する間保持し、再読み込み時は初期状態に戻ります。

設定のプリセット名をタップすると編集・削除ボタンが現れます。右の≡をドラッグすると順序を保存し、在庫の豆別まとめと登録フォームの選択肢にも反映します。ハンドルをフォーカスし↑↓キーでも並べ替えできます。入力を編集中の場合は保存またはキャンセルしてから並べ替えてください。

プリセットを選び同じ名前で登録した豆、または一致する名前で登録した豆が紐付きます。名前変更は紐付いた在庫・アーカイブへ一括反映します。豆側で別の名前に編集すると紐付けが外れます。プリセットを削除しても豆は削除されず、その時点の名前が残ります。

JSONはv6形式で購入日・補充目標・おすすめ焙煎度・消費ペース設定を保存します。以前のv1〜v5形式も取り込み、追加項目には初期値を設定します。購入日がない旧データは空欄として扱い、登録日や焙煎日から推定しません。新しいv6ファイルを旧アプリへ復元することはできません。DB v8への更新でも既存の記録を保持します。CSVには終了区分（`finishedReason`）、備考（`notes`）、購入日（`purchaseDate`）を含めます。

## おすすめ

下部タブは「在庫 / アーカイブ / おすすめ / 設定」の順です。「そろそろ買い足す」では、豆ごとに設定した未開封の目標袋数と、観測開始後に記録した飲み切り数から候補を示します。履歴による目安は30日以上かつ3袋以上の飲み切り記録が必要です。譲渡・廃棄・終了区分の未記録は消費数に含めません。袋数で計算するため、開封中の残量は反映しません。

「新しい組み合わせ」ではプリセットと焙煎度の履歴が少ない候補を最大2つ表示し、現在在庫にある同じ組み合わせを除きます。候補はその日の間はタブを移動しても保持され、「別の候補を見る」で抽選を更新できます。ブレンドは初期設定で焙煎度3に限定しています。おすすめは購入や嗜好の断定ではなく、記録に基づく目安・きっかけです。季節性と好みの学習は現時点で行いません。

おすすめ設定では「今日から記録を始める」を保存してから、以後の飲み切りを続けて記録してください。過去の記録は計測開始前の不完全な履歴である可能性があるため、消費ペースに使いません。未開封の目標数は履歴がなくても使えます。

## iPhoneで使う

1. Safariで公開URLを開き、共有メニューから「ホーム画面に追加」を選びます。
2. 「Webアプリとして開く」が表示される場合は有効にします。
3. ホーム画面のCoffeeから開き、設定に「オフライン利用の準備ができました。」と表示されるまで通信可能な状態で待ちます。
4. 以後は通信がなくても起動・在庫管理ができます。初回アクセス自体には通信が必要です。

新しいバージョンが届いたら設定に案内が出ます。入力を保存し、Safariのタブを含むCoffee Cellarの全画面を閉じて開き直すと適用されます。更新で在庫を消すことはありません。更新ファイルの取得に失敗したときは、キャッシュ済みの旧版を使います。

Safariとホーム画面アプリ、localhostと公開サイトは保存先が異なる場合があります。移行前にJSONを書き出し、移行先で復元してください。端末のブラウザデータを削除すると在庫も消えるため、JSONは端末外にも保管してください。

## バックアップと書き出し

設定の「JSONを書き出す」で全データを保存します。復元時は「JSONから復元」でファイルを選び、現在と復元後の件数を比較して「全データを置き換えて復元」を押します。復元前にも現在データを書き出せます。空のバックアップを復元すると全件削除になります。

不正形式、未知のバージョン、重複ID、状態不整合は反映前に拒否します。復元途中の中断は全ストアをロールバックします。CSVは閲覧用で復元には使えません。数式として解釈されうる自由入力はCSVでアポストロフィを補い、JSONでは元の値を保持します。

## ローカル開発

Node.js 22以降とPython 3を使います。

```sh
node scripts/prepare-pages.mjs
python3 -m http.server 4173 --bind 127.0.0.1
```

公開版相当は [http://127.0.0.1:4173/_site/](http://127.0.0.1:4173/_site/) で確認します。配信準備はファイルコピーとキャッシュの版番号生成のみで、バンドルは行いません。変更後は再びprepare-pagesを実行し、全画面を閉じて更新を適用してください。直接ソースを開く `/` も利用できますが、Service Workerの開発用版番号は固定のため、反復開発ではDevToolsで登録解除・キャッシュ削除するか `_site/` を使ってください。IndexedDBは削除不要です。

## テストと公開

```sh
npm ci
npm test
npm run test:browser
```

ブラウザテストにはGoogle Chromeが必要です。4174ポートの独立したブラウザ環境で実行し、試用中の在庫には触れません。オフラインテストでは通信を遮断し、更新テストではテスト用配信ファイルを一時的に差し替えます。

日付・入力・DB移行・名前連動・順序・JSON往復・ロールバック・CSV特殊文字に加え、ブラウザで豆別表示、ドラッグ・タッチ・キーボードの並べ替え、在庫操作、バックアップ、サブパス、オフライン、更新待機と失敗時の旧版保持を検証しています。iPhone実機のホーム画面起動・ファイル保存・機内モードでの動作は別途確認してください。

mainへのpushでGitHub ActionsがNodeテストを実行し、アプリファイルだけをPagesへ配信します。Service Workerの版番号は配信内容のハッシュから自動生成し、新旧ファイルの混在を防ぎます。テスト、開発資料、node_modulesは配信しません。
